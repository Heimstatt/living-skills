# Living Checklist — Skill Creator

*Template example. The entries below are illustrative — written to show the format, not real observations. Replace them with your own.*

**Purpose:** Experience layer for building and activating Living Skills. Permanent experience layer — not a staging area for SKILL.md.
**Karpathy principle:** Every session makes the next one better.

---

## Management

**Entry threshold:** Only add if "would go wrong again without this reminder"
**Archive rule:** Remove only when context fundamentally changed or entry superseded — NOT because it hasn't triggered recently (that may mean it's working)
**SKILL.md boundary:** Application experience stays here permanently. SKILL.md contains the authoritative skill-creation procedure — only update it when the procedure itself changes.

---

## Entry Format

```
### [DATE] — [Context/Skill built]
**Pattern found:** [What went wrong or was missed]
**Why it happened:** [Structural reason]
**Rule:** [Concrete check for future sessions]
```

---

## Entries

### YYYY-MM-DD — Principles list delivered instead of a procedure · *illustrative*
**Pattern found:** A new behavioral skill consisted of well-written principles but had no trigger, no ordered steps, no output format and no stop criterion. Sessions using it produced nothing a reviewer could check.
**Why it happened:** Principles are easy to extract from source material; procedures require deciding steps, order and the artifact each step produces.
**Rule:** Before writing, answer: "What artifact does a session using this skill hand over, and when is it done?" If the answer is only "better behavior", the skill is not finished.

---

### YYYY-MM-DD — Skill created without its companion files · *illustrative*
**Pattern found:** A skill was registered with only `SKILL.md`. The first session could not complete the activation protocol because there was no `living-checklist.md` to quote from.
**Why it happened:** The entry file feels like the skill; the checklist and revision log look like optional extras.
**Rule:** Create `SKILL.md`, `living-checklist.md` (with at least one entry) and `revisionslog.md` in the same commit, and verify all three exist before registering the skill.
